# Champions 싱글 배틀 분석기 (v6)

포켓몬 챔피언스 **싱글 배틀**용. op.gg에서 데이터를 긁어 와서 다음 네 가지를 합니다.

1. **최적 파티**: 6마리와 각자의 도구·성격·스탯포인트·기술 4개
2. **기술 배치**: 내 파티를 넣으면 기술(과 도구·성격)을 추천. 아이템 중복 금지, 메가 1마리 규칙 적용
3. **선출·선봉**: 상대 6마리를 보면 내 6마리 중 누구 3마리를 낼지, 선봉은 누구인지
4. **교체**: 배틀 중 상대 필드 포켓몬(남은 HP)을 상대로 내 남은 포켓몬 중 누구를 낼지

v5(Node 파이프라인, 09-17 수집본)는 `legacy_v5/`에 그대로 보관했습니다. 이유는 아래 "v5에서 바뀐 점"에 있습니다.

## 설치

Python 3.10 이상과 numpy만 있으면 됩니다(스크래퍼는 표준 라이브러리만 씀).

```bash
python -m pip install numpy
```

## 사용법

```bash
python -m champions scrape                 # op.gg 수집 → data/raw/<오늘 날짜>/  (싱글 순위 전 종, 약 15분, 이미 받은 건 건너뜀)
python -m champions prep                   # 전 종 세트 최적화 + 상성 행렬 → data/processed/  (첫 실행 20~30분, --pool N 으로 상위 N종만)
python -m champions team                   # 1. 최적 파티
python -m champions moves --party my.txt   # 2. 내 파티 기술 배치
python -m champions pick --party my.txt --opp 보만다,한카리아스,누리레느,하마돈,갑주무사,루카리오   # 3. 선출
python -m champions switch --party my.txt --hp 100,60,0,100,35,100 --active 마스카나 --opp 메가리자몽Y --opp-hp 70
python -m champions ui --party my.txt      # 실전 선출 보드(HTML) — 상대 6마리를 탭하면 ①선봉 ②③
python -m champions check                  # 모델 점검
```

결과는 화면에 나오고 `out/`에 마크다운으로도 남습니다. `team`은 `out/recommended_party.txt`를 만들고, 이 파일을 그대로 `--party`에 넣을 수 있습니다.

### 실전 선출 보드 (`ui`)

`out/pick_board.html` 하나로 동작하고, 인터넷이 없어도 됩니다(글꼴만 온라인일 때 적용).
- 생성할 때 내 파티 6마리와 상대 후보 **싱글 순위 전 종**(메가형 포함)의 상성을 미리 계산해 넣습니다. 동족전도 세트가 다르므로 실제 값으로 계산합니다.
- 화면에서는 상대 6마리를 목록에서 탭하거나 검색해 고릅니다. 메가 가능한 칸을 탭하면 `자동(확률) → 메가 확정 → 메가 아님` 순서로 바뀝니다.
- 결과는 3/6 선출 게임을 브라우저에서 LP로 풀어 보여줍니다.
  - **① 선봉 ② ③** 카드
  - 선출 비율, 상대 예상 선출
  - **상대 선봉별 대응**(선봉 유지인지, 누구로 교체할지)
  - 6×6 상성표
- 계산은 `pick`과 같습니다(검증: 같은 상대에서 게임 값·선출·선봉 일치).
- 파티를 바꾸면 다시 생성하세요. `--party`를 생략하면 `out/recommended_party.txt`를 씁니다.

### 파티 파일 형식

한 줄에 한 마리입니다. 이름만 적어도 되고, 아는 정보만 더 적으면 됩니다. `|`로 나눈 칸의 순서는 상관없습니다.

```
한카리아스
메가보만다                      # 메가 이름으로 쓰면 스톤을 든 것으로 봄
누리레느 @ 자뭉열매
마스카나 @ 기합의띠 | 고집 | 2/32/0/0/0/32 | 트릭플라워, 트리플악셀, 기습, 깨트리기
```

스탯포인트는 H/A/B/C/D/S 순서입니다(0~32, 합 66). `--names 한카리아스,누리레느,...`처럼 쉼표로 이어 써도 됩니다.

주요 옵션:

- `team --must 한카리아스 --exclude 메타몽 --pool 80`: 꼭 넣을 포켓몬과 뺄 포켓몬, 후보 풀 크기
- `moves --free`: 채용 70% 이상 기술도 바꿀 수 있게 함. `--keep`: 입력한 기술은 고정하고 빈 칸만 채움
- `pick --opp-mega 메타그로스`: 메가인 걸 아는 상대. 상대를 `메가리자몽Y`처럼 메가 이름으로 적어도 됨

## 데이터 (op.gg, 브라우저 없이 HTTP로)

op.gg 페이지는 Next.js RSC라서 HTML 안의 `self.__next_f.push(...)` 청크에 JSON이 들어 있습니다. `champions/scrape.py`가 청크를 이어 붙인 뒤 필요한 객체만 잘라 냅니다. robots.txt는 `User-Agent: * Allow: /`이고, 요청 사이에 1초씩 쉽니다.

| 원천 | 내용 | 파일 |
|---|---|---|
| `/tier` | 시즌 싱글 순위 262종 | `tier.json` |
| `/replica-teams?page=N` | 사용자가 제출한 팀 479개(아이템·특성·성격·스탯포인트·기술까지 완전한 빌드). 1쪽에 전체 도감 352종, 기술 920종(타수·흡수·반동·랭크변화 메타 포함), 아이템 201종 사전이 같이 들어 있음 | `replica_teams.json`, `dex.json` |
| `/pokedex/<key>` (싱글 순위 **전 종**, 시즌 M-6 기준 262종) | 포켓몬별 싱글 통계: 기술·도구·특성·성격 채용률, 스탯포인트 분포, 파트너, **가장 많이 이긴/진 상대 30**, 이길 때/질 때 기술 | `pokemon/<key>.json` |

## 모델

**1:1 전투 시뮬레이터** (`engine.py`): 레벨 50, 개체값 31. 능력치는 `HP = 종족값+75+SP`, 나머지는 `⌊(종족값+20+SP)×성격⌋`입니다. 데미지는 본가 식에 평균 난수 0.925를 곱해 씁니다. 턴마다 우선도와 스피드로 순서를 정하고 다음을 반영합니다.

- 랭크 변화: 쌓기기, 용성군류 자기 하락, 상대 하락기, 위협과 그 반응 특성
- 반동·흡수(기술 메타의 drain 값), 생명의구슬, 울퉁불퉁멧, 까칠한피부
- 기합의띠, 옹골참, 탈, 멀티스케일, 자뭉열매, 반감 열매, 풍선, 스카프 고정
- 날씨·필드 특성(메가진화로 켜지는 날씨가 나중에 발동), 스킨류, 적응력, 변환자재, 테크니션, 확정 급소기, 연속기 타수
- 화상·독·마비·잠듦·씨뿌리기, 속박기(엉겨붙기·회오리불꽃 등, 5턴 동안 1/8, 조임밴드 1/6), 회복기, 반동 턴, 모으기 기술, 기습·속이기 조건, 날려버리기·흑안개
- **PP**: 기술마다 PP를 세고, 다 떨어지면 발버둥을 씁니다. 회복전은 임의 횟수가 아니라 PP로 끝납니다.
- 속이기: 첫 턴에만 쓸 수 있고 상대를 풀죽게 합니다. 정신력·인분과 사이코필드에는 막힙니다.
- 변환자재·리베로: 등장 후 첫 기술 때 **막는 타입까지** 그 기술 타입으로 바뀝니다(1회). 이후 자속은 바뀐 타입 기준입니다.
- 깨어진갑옷: 물리기를 맞으면 방어 −1, 스피드 +2가 됩니다.
- 연속기는 기합의띠와 옹골참을 뚫습니다. 탈은 첫 타만 막습니다.

**행동 규칙**
- "잡을 수 있다"는 실제로 들어갈 피해로 판정합니다. 기대값 모드는 명중을 곱한 피해, 확률 모드는 맞았을 때 피해입니다(예전에는 90% 기술의 맞았을 때 피해로 판정해서, 파멸의빛처럼 못 잡고 반동만 맞는 수를 골랐습니다).
- 잡을 수 있으면 잡습니다. 반동으로 같이 쓰러지지 않는 기술을 우선하고, 그다음 우선도·명중·반동이 적은 순입니다.
- 못 잡으면 (상대 남은 HP 중 깎는 비율 × 명중) − (내 HP 중 반동 비율) + 흡수 회복이 가장 큰 기술을 씁니다. 깎는 양은 상대 남은 HP에서 자르므로 넘치는 위력은 값이 없고, 반동으로 자멸하는 수는 피합니다.
- 회복은 **이번 행동 뒤 다음 한 대에 쓰러질 때만** 씁니다. 느린 쪽은 맞은 뒤 HP로 판단합니다. 그래서 더시마사리처럼 회복과 엉겨붙기를 교대로 씁니다.
- 먼저 쓰러진 쪽이 집니다. 턴 종료 화상·반동으로 둘 다 쓰러지면 먼저 쓰러진 쪽 기준입니다.

각 포켓몬은 계획을 하나 고릅니다. 계획은 다음 중 하나입니다.
- 그냥 때리기
- 쌓기 1~2회 후 때리기
- 상태이상 먼저
- 기습을 쓰지 않고 때리기: 기습 보유자만 해당합니다. 상대가 변화기로 기습을 헛치게 하는 수를 읽는 경우입니다.

계획 쌍마다 끝까지 돌려서 계획 행렬을 만들고, 그 **행렬 게임의 혼합전략 균형값**을 v ∈ [−1, 1]로 씁니다(이기면 +0.5 + 0.5×남은 HP). 안장점이 있으면 순수전략 값과 같고, 없으면(예: 도깨비불 ↔ 기습 읽기) `game.py`의 LP로 풉니다. 60턴 안에 안 끝나면 0.5×(내 HP 비율 − 상대 HP 비율)이고 범위는 ±0.5입니다. 3:3 맥락을 반영하려고 **정면 60% + 내가 교체로 들어가 한 대 맞고 시작 20% + 상대가 그렇게 들어옴 20%**로 섞습니다. 그래서 반대칭입니다.

**두 가지 모드**: 기대값 모드는 명중을 곱하고 난수 0.925, 마비는 피해 ×0.75로 처리합니다. 결정적이고 빠르며 세트 최적화와 팀 탐색에 씁니다. 확률 모드는 명중, 난수 0.85~1.00, 급소 1/24, 마비 25%, 잠듦 1~3턴을 N판 굴려 평균값과 **승률**을 냅니다. `switch`(기본 64판)와 `pick --mc N`에 씁니다.

엔진 점검: `python -m champions.trace 킬라플로르 더시마사리`로 한 판을 턴별로 재생합니다(계획 행렬과 턴마다의 HP 변화).

**실전 신호 혼합**: op.gg의 "많이 이긴 상대 / 많이 진 상대" 순위 차이를 신호 E로 만들어 `V = 0.8·시뮬 + 0.2·E`로 섞습니다. 두 목록 모두 상대 등장 빈도에 끌려가기 때문에 순위의 **차이**만 씁니다.

**점검**
- `check`: 신호가 있는 상위 50종 1,014쌍에서 시뮬레이션(혼합 전)과 E의 스피어만 **ρ = 0.645**입니다. 09-23 audit 반영 전에는 0.632였고, v5는 인기 순위와만 비교할 수 있었으며 ρ ≈ 0.50이었습니다.
- `audit`: 외부 심판(gpt-6-astra) 점검입니다. 20쌍씩, 심판 답은 캐시에서 읽었습니다.

| | seed 7 | seed 8 |
|---|---|---|
| 최초 | 17/20 | 15/20 (1차 수정 후 처음 본 표본) |
| 1차 수정 후 (회복·PP·속박·반동·기습) | 20/20 | 15/20 |
| **2차 수정 후** (속이기·변환자재·깨어진갑옷·연속기·잡기 판정) | **18/20** | **18/20** |
| ρ(시뮬, op.gg 실전) / ρ(심판, 실전) | 0.78 / 0.78 | 0.86 / 0.88 |

2차 수정 후 남은 불일치 4건은 추적(`champions.trace`)과 손계산으로 확인했습니다. 모두 **시뮬이 맞다고 판단합니다**.

| 매치업 | 판단 근거 |
|---|---|
| 마스카나 vs 메가마폭시 | 탁쳐서떨구기로 악 타입이 된 뒤 화염방사 130/153으로 버팁니다. 심판은 변환자재를 무시했습니다. seed 7의 20/20은 변환자재 버그가 우연히 심판과 맞은 결과였습니다. |
| 메가이어롭 vs 고릴타 | 속이기 → 트리플악셀 → 마하펀치 순입니다. 마하펀치와 그래스슬라이더가 둘 다 +1 우선도라 이어롭이 먼저 칩니다. |
| 메가리자몽Y vs 패리퍼 | 심판 질문이 메가를 처음부터 진화한 상태로 적어 날씨 순서가 틀렸습니다. 질문 문장 오류입니다. |
| 더시마사리 vs 메가입치트 | 맹독은 강철에게 막힙니다. 엉겨붙기 지속 피해, 회복, 흑안개(칼춤 초기화)로 이깁니다. 사실상 소모전입니다. |

`check`(op.gg 실전 신호, 1,014쌍, 표본 외 검증): 0.632 → 0.645 → 0.642 → **0.628**. 2차 수정에서는 사실상 변화가 없었습니다.

마지막 0.628은 상대 대표 세트를 실제 한 벌로 바꾼 결과입니다. 분해해 보면 혼합전략 풀이의 영향은 0이고, 하락은 전부 세트 교체에서 왔습니다. 실제 세트에 섞인 스텔스록·하품·방어 같은 기술은 시뮬이 값을 매기지 못해서 상대가 약하게 계산됩니다. 차이는 순위상관 표본오차(약 0.03) 안이라서, 실제로 만나는 세트를 쓰는 쪽을 택했습니다.

상대 세트가 바뀌면서 `audit` 질문 문장도 바뀌었습니다. 그래서 seed 7·8 심판 캐시는 **1/20만 유효**하고, 다시 확인하려면 유료 호출이 필요합니다.

**상대 메타**: 상대 한 개체는 "포켓몬 × 메가 여부" 단위입니다.
- 대표 세트: 레플리카 팀에 같은 개체 빌드가 3개 이상 있으면, **그중 나머지와 가장 닮은 실제 빌드 한 벌(메도이드)을 통째로** 씁니다.
  - 예전에는 성격·배분·도구·기술을 항목별 최빈값으로 따로 뽑아서, 아무도 쓰지 않는 조합이 생길 수 있었습니다.
  - 실제 세트라서 스텔스록·하품·방어처럼 시뮬이 값을 못 매기는 기술도 그대로 들어갑니다.
- 레플리카 빌드가 부족하면 op.gg 최다 배분에, 그 배분과 맞는 성격 중 최다를 짝지웁니다.
- 조우 가중치: 레플리카 싱글 팀(**중복 제거**)에 나온 횟수에 싱글 순위 사전값을 더해 정합니다.
- **범위는 op.gg 싱글 순위 전 종**입니다(M-6: 262종, 레플리카에만 있는 변형 폼 포함 시 상대 269종·메가형 포함 개체 345개).
  - 순위가 낮은 포켓몬도 빠지지 않습니다. 사전값에 바닥값을 두어 작은 가중치로 들어갑니다.
  - 팀 후보 풀도 기본값이 전 종입니다.
- 도감에서 빠지는 것은 외형 변형 8종뿐입니다(암컷 모습, 깃털색 등). 이들은 op.gg 순위나 통계가 따로 없습니다.
- **메타몽(괴짜)**: 등장하자마자 상대로 변신합니다. HP를 뺀 능력치·타입·특성·기술(PP 5)을 복사하고 자기 도구(스카프·띠 등)는 유지합니다. 세트 최적화는 도구와 HP 투자만 고릅니다(`변신형`).

**세트 최적화** (`sets.py`): 실채용 최다 세트에서 출발해 한 칸 바꾸기를 개선이 없을 때까지 반복합니다(정면 1:1 값, 빠름). 그다음 도구, 성격·스탯포인트를 교체 등장까지 섞은 값으로 고릅니다. 마지막으로 **같은 목표(교체 등장 포함)로 기술을 한 번 더 다듬어** 기술과 도구의 목표를 맞춥니다. 후보는 다음과 같습니다.

- op.gg 채용 3% 이상인 기술
- 배울 수 있는 공격기 중 타입·분류별 최강 1개
- 쌓기·회복·상태이상기는 채용 10% 이상일 때만

채용 70% 이상 기술은 고정합니다. 모델이 값을 매기지 못하는 기술(스텔스록·방어·교체기의 교체 이득 등)이 여기에 해당하기 때문입니다.

**공격 유형**: 세트는 유형을 먼저 정하고, 성격·스탯포인트·기술이 모두 그 유형과 맞아야 후보가 됩니다. 예전에는 특수 투자(조심, C32)를 한 망나뇽에게 무투자 지진·신속이 들어가는 식으로 의도가 불분명한 세트가 나왔습니다.

| 유형 | 성격 | 스탯포인트 | 공격기 | 쌓기기 |
|---|---|---|---|---|
| 물리형 | 공격↓·특공↑ 금지 | 특공 ≤ 4 | 물리만 | 공격을 올리거나 방어·스피드만 올리는 것 |
| 특수형 | 특공↓·공격↑ 금지 | 공격 ≤ 4 | 특수만 | 특공을 올리거나 방어·스피드만 올리는 것 |
| 쌍두형 | 공격↓·특공↓ 금지 | 공격·특공 각 ≥ 8 | 물리 1개 이상 **그리고** 특수 1개 이상 | 제한 없음 |

- 종족값이나 op.gg 채용상 말이 되는 유형마다 따로 최적화하고, 가장 높은 유형을 추천합니다. 높은 쪽 공격 스탯의 유형은 항상 보고, 낮은 쪽은 그 스탯이 높은 쪽의 80% 이상이거나 그 분류 공격기 채용 합이 25% 이상일 때만 봅니다. 쌍두형은 두 유형이 모두 가능할 때 봅니다.
- `moves` 출력에 유형별 최고 점수를 같이 보여줍니다. 파티 파일에 `물리형`/`특수형`/`쌍두형`을 적으면 그 유형으로만 추천합니다.
- 고정 기술(채용 70% 이상이거나 `--keep`)이 유형과 충돌하면 그 유형은 제외합니다. 모든 유형과 충돌하면 쌍두형으로 처리합니다.
- op.gg에서 가져온 상대 대표 세트는 실제 채용을 합친 것이라 유형 규칙을 적용하지 않습니다. 표시는 `비정형(…)`으로 나올 수 있습니다.

**역할**: 공격 분류와 별개로, 세트가 "때리는 쪽"인지 "버티는 쪽"인지 정합니다. 표시는 `물리 공격형`, `특수 내구형`처럼 합쳐서 나옵니다.

| 역할 | 스탯포인트 | 성격 | 도구 |
|---|---|---|---|
| 공격형 | 공격 스탯 ≥ 16 (쌍두형은 둘 다 ≥ 8) | 공격 스탯이나 스피드를 올리거나 무보정 | 생명의구슬·구애스카프·기합의띠·달인의띠·타입 강화 도구는 공격형만 |
| 내구형 | 공격 스탯 < 16, HP + (방어 또는 특방) ≥ 40 | 방어나 특방을 올리고, 둘 다 내리지 않음 | 울퉁불퉁멧은 **물리 방어 투자(방어 ≥ 16 또는 방어↑ 성격)가 있는 내구형만** |

- 먹다남은음식·자뭉열매·리샘열매 등은 두 역할 모두 쓸 수 있습니다.
- 구애스카프는 쌓기·회복·변화기와 같이 쓰지 않습니다. 기술이 하나로 고정되기 때문입니다.
- 내구형은 회복기가 후보에 있거나 실제 내구형 배분이 관측될 때만 따로 최적화합니다. 쌍두형은 공격형만 봅니다.
- 성격·스탯포인트 후보 순서:
  1. **레플리카 팀에 실제로 같이 쓰인 (성격, 배분) 짝**
  2. op.gg 성격 × op.gg 배분 조합 중 규칙을 통과하는 것
  3. 역할별 정석(고집 A32 S32, 장난꾸러기 H32 B32 등)
- 예전에는 op.gg가 성격과 배분을 따로만 줘서 둘을 곱해 조합을 만들었습니다. 그 결과 "고집 + H31 B25 S10(원래는 장난꾸러기 헬멧 망나뇽의 배분) + 울퉁불퉁멧 + 공격기 4개"처럼 아무도 쓰지 않는 세트가 나왔습니다.

**팀 탐색** (`team.py`): 선출 게임은 서로 6마리를 보고 3마리씩 내는 방식입니다. 내 3 대 상대 3의 값은 "상대 한 마리마다 내 최선의 답"과 "내 한 마리마다 상대의 최악 카운터"의 평균입니다. 팀 대 팀 값은 20×20 선출 게임의 값이고, 팀 점수는 이 값을 레플리카 싱글 팀 전체에 대해 평균한 것입니다. 제약은 종 중복 금지, 아이템 중복 금지, 메가 스톤 1장 이하입니다.
- 탐색: 탐욕 시작과 무작위 재시작 후 한 장 바꾸기로 국소 탐색합니다. 이어서 **같은 6종의 도구 변형 조합을 전부**(최대 3^6) 봅니다. 한 장 바꾸기로는 못 하는 "두 마리 도구 맞바꾸기"를 처리하기 위해서입니다. 이 단계의 게임 값은 속도 때문에 순수전략 하한·상한 평균(근사)을 씁니다.
- 최종: 상위 20개 후보를 **혼합전략 균형값(LP, 정확)**으로 다시 줄 세웁니다. 상대 팀 표본을 부트스트랩해 후보별 1위 확률과 표준오차도 구합니다. 탐색에 쓴 표본을 다시 써서 1위 확률은 낙관적입니다(승자의 저주).
- `pick`도 같은 20×20 게임을 LP로 풉니다. 균형에서 가장 자주 낼 3마리를 추천하고, 선출 혼합 비율과 상대 선출 예상 분포를 같이 보여줍니다.

추천 팀은 이렇게 고릅니다.
- 먼저 1위와 통계적으로 구분되지 않는 후보를 모읍니다. 기준은 **같은 상대 표본에서의 대응 차이**가 2 표준오차 안입니다. 후보들은 멤버를 대부분 공유하므로 팀별 SE가 아니라 이 대응 차이로 판정합니다.
- 그 안에서 무답 노출(값 ≥ 0인 카드가 2장 미만인 상대의 비중)이 1%p 이상 작은 팀을 우선하고, 나머지는 팀 값이 높은 팀을 고릅니다.

## 한계

- **모델 밖**: 3:3을 이어서 도는 평가(교체, 설치기·킬러스핀 제거, 기합의띠 소모가 다음 매치업으로 넘어가는 것), 교체 이득(유턴·볼트체인지·재생력), 도발·앵콜, 방어, 트릭룸, 하품. 팀 값은 여전히 1:1 값의 선출 게임 합산입니다.
- op.gg 승패 신호의 혼합 가중치 0.2는 근거가 약합니다(ASTRA 지적 3). 신호 자체가 검증 지표라서 같은 데이터로 튜닝하면 과적합이 됩니다. 다른 날짜의 수집본이 생기면 그 데이터로 0~0.4를 비교해 정할 예정입니다.
- `switch`는 랭크 변화·필드·남은 파티 구성을 반영하지 않습니다(ASTRA 지적 4, 3:3 시뮬레이션과 함께 보류).
- 명중·급소·난수 분산은 `switch`와 `pick --mc`에서만 확률로 봅니다. 팀 탐색과 세트 최적화는 기대값 모드입니다.
- 모든 "최적/추천"은 이 가정 아래의 **후보**입니다. 승률 예측이 아닙니다.
- 레플리카 팀은 사용자가 제출한 팀이라 래더 전체와 분포가 다를 수 있습니다.
- op.gg 기술 통계는 상위 10개만 줍니다. 그 밖의 기술은 배울 수 있는 기술 목록에서 후보로 넣습니다.
- 메가 가능 여부나 스톤 판정은 op.gg 도감 기준입니다(시즌 M-6: 메가 82종).
