# 기본 로직 검토 (gpt-6-astra): 적정성 **partly**

개선은 유효하지만 팀 탐색과 선출에서 메가·역할 유형의 일관성이 깨져 추천 순위가 왜곡된다.

1. [high] `opponent_space → TeamSearch.team_values` — 스톤 보유자를 모두 메가 개체로 넣어, 상대가 스톤 두 장을 선출하면 두 마리 모두 진화한 상성으로 팀을 평가한다.
   → 팀 탐색에도 스톤 보유와 진화 상태를 분리하고, 선출별 실제 메가 사용자는 최대 한 마리로 제한한다.
2. [high] `advise → matchup → value_vs` — 역할 불확실성을 개별 대면에서 먼저 축약한다. 선출 게임의 유형은 스톤뿐이라 상대가 자기 역할 세트에 맞춰 선출하는 대응이 빠진다.
   → 역할·스톤의 팀 단위 유형을 표본화하고, 유형별 선출 행렬을 solve_bayes에 전달한다.
3. [high] `mega_scenarios, scenario_pick_matrices` — 진화하지 않은 스톤 보유자에게 Vb의 비스톤 도구를 적용한다. 두 스톤 선출 시 미진화 개체가 실제로 없는 도구 효과를 얻는다.
   → 비스톤 기본형과 스톤 보유 미진화형을 별도로 만들고, 시나리오의 모든 보유 슬롯에 올바른 도구 상태를 적용한다.
4. [high] `opp_variants, advise, stone_sets` — 스톤 하나가 확인되면 다른 보유 가능성을 모두 삭제한다. 또한 forced 관측 후 스톤 수 분포를 관측 가능도로 갱신하지 않는다.
   → 스톤 확인과 메가 사용 완료를 구분한다. 전체 조합 사전분포에서 관측과 모순되는 조합만 제거하고 정규화한다.
5. [medium] `switch` — active=None이거나 기존 출전자가 기절해도 모든 후보에 pre_hit=True를 적용하여 무상 등장에 피격 비용을 부과한다.
   → 자발적 교체와 기절 후 출전을 명시적으로 구분하고, 자발적 교체에만 선제 피격을 적용한다.
6. [medium] `attach_variants, make_alt` — 미지원 기술을 공격기로 바꾼 가상 세트에 역할 확률의 절반을 부여한다. 구현 불확실성을 실제 채용 확률로 둔갑시킨다.
   → 관측 세트의 확률은 유지하고 가상 변형은 별도 민감도 시나리오로 평가한다.
7. [medium] `_optimize_arch, optimize` — 결정적 평가로 유형별 후보 하나만 남긴 뒤 분기 평가한다. 분기 평가에서 우수한 같은 유형의 기술·도구 조합은 이미 버려진다.
   → 유형별 상위 후보를 보존해 분기 재평가하고, 최종 후보 주변 기술·도구 교체를 분기 목표로 재탐색한다.
